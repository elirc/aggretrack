# AggreTrack — Data Model (source of truth)

Implementers: names below are FINAL. Use them exactly — SQL names snake_case, Drizzle export names camelCase of the same word (e.g. table `purchase_lines` → `purchaseLines`). Schema lives in `src/db/schema/` split by module: `auth.ts` (Better Auth generated), `org.ts`, `master.ts`, `suppliers.ts`, `purchases.ts`, `stock.ts`, `sales.ts`, `logistics.ts`, `billing.ts`, `system.ts`, re-exported from `src/db/schema/index.ts`.

## Global conventions

- **ids**: business tables → `uuid` PK `default gen_random_uuid()`. Offline-created records (purchases, purchase_lines, purchase_line_deductions, dispatches) accept a **client-generated UUID as the PK**; the PK uniqueness IS the idempotency guarantee — sync re-insert conflicts are detected with `on conflict (id) do nothing` + existence check.
- **Auth-owned ids are `text`** (Better Auth generates text ids). Every FK into `user` or `organization` is `text`. Business↔business FKs are `uuid`.
- **organisation_id**: `text not null references organization(id)` + index on EVERY business table. Column name is exactly `organisation_id`.
- **Money**: `bigint` integer **kobo**, column suffix `_kobo`. Per-kg *derived* rates (landed cost) are `numeric(14,4)` kobo/kg. Entered prices (`price_per_kg_kobo`, `max_price_per_kg_kobo`) are integer kobo `bigint`.
- **Weights**: `numeric(12,3)` kg, suffix `_kg`. Bags: `integer`.
- **Timestamps**: `timestamptz`, UTC. Every table: `created_at timestamptz not null default now()`, `updated_at timestamptz not null default now()`. Business dates that are calendar dates (purchase_date, trip_date, guide date, invoice due_date) are `date`.
- **created_by**: `text references user(id)` on every user-entered table.
- Soft deletes: none. Cancellation is a status.

## Auth tables (Better Auth — generated, do not hand-design)

`user`, `session`, `account`, `verification`, `organization`, `member`, `invitation` are generated by `npx @better-auth/cli generate` with the **phoneNumber** and **organization** plugins and the drizzle adapter. Extensions we configure, not invent: `user.phoneNumber` + `user.phoneNumberVerified` (phoneNumber plugin), `user` additionalField `is_platform_admin boolean default false`, `member.role` stores an `org_role` value as text. Output goes to `src/db/schema/auth.ts`.

## Org extensions (`org.ts`)

### organisation_settings — 1:1 with organization
- `organisation_id text PK references organization(id)`
- `currency text not null default 'NGN'`, `timezone text not null default 'Africa/Lagos'`
- `adjustment_approval_threshold_kg numeric(12,3) not null default 50`
- `low_stock_threshold_kg numeric(12,3) not null default 1000`
- `old_stock_days integer not null default 90`
- `capacity_alert_percent integer not null default 90`
- `hide_prices_from_warehouse boolean not null default false`
- `invoice_tax_percent numeric(5,2) not null default 0` (tax line off by default)
- `setup_completed_at timestamptz` (null until wizard finishes)

### member_warehouse_access
- `id uuid PK`, `organisation_id`, `member_id text not null references member(id) on delete cascade`, `warehouse_id uuid not null references warehouses(id)`
- unique `(member_id, warehouse_id)`. **No rows for a member = all warehouses allowed.**

### member_buying_point_access
- same shape with `buying_point_id`. No rows = all buying points.

## Master data (`master.ts`) — all have id uuid PK, organisation_id, created_at/updated_at, unique `(organisation_id, name)`, index on organisation_id

- **commodities**: `name text not null`, `code text not null` (unique `(organisation_id, code)`), `active boolean not null default true`
- **grades**: `commodity_id uuid not null references commodities(id)`, `name`, `code`; unique `(commodity_id, name)`
- **bag_types**: `name`, `standard_kg numeric(12,3) not null`, `sack_weight_kg numeric(12,3) not null default 0`
- **buying_points**: `name`, `lga text`, `state text`, `active boolean default true`
- **warehouses**: `name`, `location text`, `capacity_kg numeric(12,3)`, `active boolean default true`
- **bins**: `warehouse_id uuid not null references warehouses(id)`, `name`; unique `(warehouse_id, name)`
- **vehicles**: `plate_number text not null` (unique per org), `description text`, `capacity_kg numeric(12,3)`
- **drivers**: `name`, `phone text`, `licence_note text`
- **expense_categories**: `name`, `affects_landed_cost boolean not null default false` (handling/loading categories flagged true share into lot landed cost when attached to an inbound trip or lot)

### price_guides
- `commodity_id`, `grade_id uuid references grades(id)` (null = all grades), `buying_point_id uuid references buying_points(id)` (null = all points), `guide_date date not null`, `max_price_per_kg_kobo bigint not null`, `created_by`
- unique `(organisation_id, commodity_id, grade_id, buying_point_id, guide_date)`; index `(organisation_id, guide_date)`
- Lookup rule: most specific match wins (exact grade+point > grade+null point > null grade+point > both null), latest `guide_date <= purchase_date`.

## Suppliers (`suppliers.ts`)

### suppliers
- `type supplier_type not null`, `name text not null`, `phone text`, `village text`, `lga text`, `state text`
- `bank_name text`, `bank_account_number text`, `bank_account_name text`, `id_note text`, `photo_key text` (storage adapter key)
- index `(organisation_id, name)`, index `(organisation_id, phone)`

### supplier_advances
- `supplier_id uuid not null references suppliers(id)`, `advance_number text not null` (ADV, gapless), `amount_kobo bigint not null`, `advance_date date not null`, `note text`, `created_by`
- unique `(organisation_id, advance_number)`
- Outstanding = amount − Σ supplier_advance_offsets. No status column; derived.

### supplier_payments
- `supplier_id`, `payment_number text` (SPM), `amount_kobo bigint not null`, `method payment_method not null`, `payment_date date not null`, `reference text`, `note text`, `created_by`
- unique `(organisation_id, payment_number)`

### supplier_payment_allocations
- `payment_id uuid not null references supplier_payments(id) on delete cascade`, `purchase_id uuid references purchases(id)`, `advance_id uuid references supplier_advances(id)`, `amount_kobo bigint not null`
- CHECK exactly one of purchase_id/advance_id is non-null. Allocation to an advance = this payment funded/disbursed that advance.

### supplier_advance_offsets — recovery of an advance against a purchase payable
- `advance_id uuid not null references supplier_advances(id)`, `purchase_id uuid not null references purchases(id)`, `amount_kobo bigint not null`, `created_by`

> Two allocation tables (supplier vs customer) instead of one polymorphic table: real FKs and simpler queries beat shared shape.

**Supplier balance** (owed TO supplier, positive): Σ received-purchase `total_amount_kobo` − Σ payment allocations to purchases − Σ advance offsets. **Owed BY supplier**: Σ advances − Σ offsets.

## Purchases (`purchases.ts`)

### purchases
- `id uuid PK` (client-generated offline)
- `purchase_number text` (PO, assigned server-side on first sync/save — nullable until numbered, unique `(organisation_id, purchase_number)`)
- `supplier_id`, `buying_point_id`, `officer_id text not null references user(id)` (the procurement officer; = created_by normally)
- `purchase_date date not null`, `status purchase_status not null default 'draft'`
- `total_amount_kobo bigint not null default 0` (denormalised Σ lines, recomputed in-tx)
- Price-guide approval inline: `requires_approval boolean not null default false`, `approved_by text references user(id)`, `approved_at timestamptz`, `rejected_reason text`
- Offline provenance: `created_offline boolean not null default false`, `client_created_at timestamptz`
- Receiving: `received_warehouse_id uuid references warehouses(id)`, `received_at timestamptz`, `grn_number text`, `grn_document_id uuid references documents(id)`
- indexes: `(organisation_id, purchase_date)`, `(organisation_id, supplier_id)`, `(organisation_id, status)`

### purchase_lines
- `id uuid PK` (client-generated offline), `purchase_id uuid not null references purchases(id) on delete cascade`, `organisation_id`
- `commodity_id`, `grade_id`, `bag_type_id uuid references bag_types(id)`
- `bags integer not null default 0`, `gross_kg numeric(12,3) not null`, `net_kg numeric(12,3) not null`, `moisture_percent numeric(5,2)`
- `price_per_kg_kobo bigint not null`, `amount_kobo bigint not null`
- `over_guide boolean not null default false` (price exceeded guide at entry time)

### purchase_line_deductions
- `id uuid PK`, `purchase_line_id uuid not null on delete cascade`, `organisation_id`, `reason deduction_reason not null`, `kg numeric(12,3) not null`, `note text`
- (Separate table, not jsonb — supplier quality-deduction history needs grouping by reason.)

## Stock (`stock.ts`)

### lots
- `lot_number text not null` (LOT, gapless), unique `(organisation_id, lot_number)`
- `commodity_id`, `grade_id`, `supplier_id`, `purchase_line_id uuid not null references purchase_lines(id)` unique (1 line = 1 lot)
- `received_at timestamptz not null`, `original_kg numeric(12,3) not null`, `original_bags integer not null default 0`
- `purchase_price_per_kg_kobo bigint not null`
- `landed_cost_per_kg_kobo numeric(14,4) not null` (initialised = purchase price; recomputed when trip costs/expenses attach)
- indexes `(organisation_id, commodity_id, grade_id)`, `(organisation_id, received_at)`

### stock_movements — APPEND-ONLY. No update, no delete, ever. Corrections are new rows.
- `lot_id uuid not null references lots(id)`, `warehouse_id uuid not null`, `bin_id uuid references bins(id)`
- `type movement_type not null`, `kg numeric(12,3) not null` (**SIGNED**: receive/transfer_in/return > 0; transfer_out/dispatch < 0; adjustment either), `bags integer not null default 0` (signed, same convention)
- `ref_type doc_type`, `ref_id uuid` (the GRN purchase, transfer, dispatch, adjustment row), `created_by`, `occurred_at timestamptz not null default now()`
- CHECK: `(type in ('receive','transfer_in','return') and kg > 0) or (type in ('transfer_out','dispatch') and kg < 0) or (type = 'adjustment')`
- indexes `(organisation_id, lot_id)`, `(organisation_id, warehouse_id)`, `(organisation_id, occurred_at)`, `(lot_id, warehouse_id)`

### transfers
- `transfer_number text not null` (TRF), `from_warehouse_id`, `to_warehouse_id`, `status transfer_status not null default 'draft'`
- `dispatched_at timestamptz`, `received_at timestamptz`, `created_by`
- CHECK from ≠ to; unique `(organisation_id, transfer_number)`

### transfer_lines
- `transfer_id on delete cascade`, `organisation_id`, `lot_id`, `kg numeric(12,3) not null`, `bags integer default 0`, `received_kg numeric(12,3)`, `received_bags integer`, `loss_kg numeric(12,3)` (= kg − received_kg, set at receipt)
- In-transit stock = lines of transfers with status `in_transit` (transfer_out already posted, transfer_in not yet). The loss needs NO extra movement: out −kg, in +received_kg nets the loss out of global stock correctly.

### stock_counts
- `count_number text` (CNT), `warehouse_id`, `status count_status default 'draft'`, `counted_at timestamptz not null`, `posted_at timestamptz`, `created_by`

### stock_count_lines
- `count_id on delete cascade`, `organisation_id`, `lot_id`, `bin_id`, `counted_bags integer`, `counted_kg numeric(12,3) not null`, `system_kg numeric(12,3) not null` (snapshot at entry), `diff_kg numeric(12,3) not null` (= counted − system)

### adjustments
- `adjustment_number text` (ADJ), `lot_id`, `warehouse_id`, `bin_id`, `reason adjustment_reason not null`, `kg numeric(12,3) not null` (signed), `bags integer default 0`
- `status adjustment_status not null default 'pending_approval'`, `approved_by`, `approved_at`, `rejected_reason text`, `source_count_id uuid references stock_counts(id)`, `note text`, `created_by`
- Below org threshold → service auto-approves and posts in one tx (status `posted` immediately). Movement row written only on post.

## Sales (`sales.ts`)

### customers
- `name not null`, `phone`, `email`, `address text`, `state text`, `note text`; index `(organisation_id, name)`

### sales_orders
- `order_number text` (SO), `customer_id`, `order_date date not null`, `status sales_order_status default 'draft'`, `total_amount_kobo bigint not null default 0`, `created_by`

### sales_lines
- `sales_order_id on delete cascade`, `organisation_id`, `commodity_id`, `grade_id`, `kg numeric(12,3) not null`, `price_per_kg_kobo bigint not null`, `amount_kobo bigint not null`

### lot_allocations — reservation layer, NOT movements
- `sales_line_id`, `lot_id`, `warehouse_id uuid not null`, `kg numeric(12,3) not null`, `status allocation_status not null default 'reserved'`, `created_by`
- index `(lot_id, warehouse_id, status)`
- **available(lot, warehouse) = Σ movements.kg − Σ allocations.kg where status='reserved'**. Dispatch flips reserved→dispatched in the same tx that writes the dispatch movement (so it never double-counts).

### dispatches
- `id uuid PK` (client-generated offline-capable), `waybill_number text` (WB), `sales_order_id`, `vehicle_id`, `driver_id`, `status dispatch_status default 'in_transit'`
- `dispatched_kg numeric(12,3) not null`, `delivered_kg numeric(12,3)`, `transit_loss_kg numeric(12,3)` (set on delivery), `dispatched_at timestamptz not null`, `delivered_at timestamptz`, `waybill_document_id uuid references documents(id)`, `created_by`

### dispatch_lines
- `dispatch_id on delete cascade`, `organisation_id`, `lot_allocation_id uuid not null references lot_allocations(id)`, `kg numeric(12,3) not null`

### invoices
- `invoice_number text` (INV), `customer_id`, `sales_order_id`, `dispatch_id uuid references dispatches(id)`, `invoice_date date not null`, `due_date date`
- `subtotal_kobo bigint not null`, `tax_percent numeric(5,2) not null default 0`, `tax_kobo bigint not null default 0`, `total_kobo bigint not null`
- `status invoice_status default 'issued'`, `document_id uuid references documents(id)`, `created_by`
- Outstanding = total − Σ allocations; status derived part_paid/paid as allocations land.

### customer_payments
- `customer_id`, `payment_number text` (CPM), `amount_kobo`, `method payment_method`, `payment_date date`, `reference`, `note`, `created_by`

### customer_payment_allocations
- `payment_id on delete cascade`, `invoice_id not null`, `amount_kobo bigint not null`

## Logistics (`logistics.ts`)

### trips
- `trip_number text` (TRP), `direction trip_direction not null`, `vehicle_id`, `driver_id`, `origin text`, `destination text`, `trip_date date not null`, `cost_kobo bigint not null default 0`, `note`, `created_by`

### trip_purchases — join: `trip_id`, `purchase_id`, unique pair, `organisation_id`
### trip_dispatches — join: `trip_id`, `dispatch_id`, unique pair, `organisation_id`

### expenses
- `expense_number text` (EXP — add `exp` to doc_type enum), `category_id uuid not null references expense_categories(id)`, `amount_kobo bigint not null`, `expense_date date not null`
- Attachment (0 or 1 of): `lot_id uuid references lots(id)`, `trip_id uuid references trips(id)`, `warehouse_id uuid references warehouses(id)` — CHECK at most one non-null
- `note`, `created_by`

## Billing (`billing.ts`)

### plans — global, NO organisation_id
- `code text unique not null`, `name`, `monthly_price_kobo bigint not null`, `user_limit integer not null`, `paystack_plan_code text`, `active boolean default true`

### subscriptions
- `organisation_id text unique not null`, `plan_id uuid not null references plans(id)`, `status subscription_status not null default 'trialing'`
- `trial_ends_at timestamptz not null`, `current_period_end timestamptz`, `paystack_customer_code text`, `paystack_subscription_code text`, `paystack_email_token text`
- Read-only rule: org is read-only when `status='past_due'`, `status='cancelled'`, or (`trialing` and `trial_ends_at < now()`). Enforced in the server-action guard, never by deletion.

## System (`system.ts`)

### document_counters — gapless numbering
- `organisation_id text not null`, `doc_type doc_type not null`, `year integer not null`, `last_number integer not null default 0`
- PK `(organisation_id, doc_type, year)`
- Allocation (same tx as the row that consumes the number — rollback releases it, no gaps):
  `INSERT INTO document_counters VALUES ($org,$type,$year,1) ON CONFLICT (organisation_id,doc_type,year) DO UPDATE SET last_number = document_counters.last_number + 1 RETURNING last_number;`
- Format: `{PREFIX}-{year}-{number padded to 5}` → `GRN-2026-00001`. Prefix map: po→PO, grn→GRN, lot→LOT, trf→TRF, wb→WB, so→SO, inv→INV, adj→ADJ, cnt→CNT, adv→ADV, spm→SPM, cpm→CPM, trp→TRP, exp→EXP.

### documents
- `type doc_type not null`, `number text`, `ref_type doc_type`, `ref_id uuid`, `storage_key text not null`, `mime text not null default 'application/pdf'`, `size_bytes integer`, `created_by`
- index `(organisation_id, ref_type, ref_id)`

### notifications
- `user_id text references user(id)` (null = all org users), `type notification_type not null`, `title text not null`, `body text`, `link text`, `read_at timestamptz`
- index `(organisation_id, user_id, read_at)`

### audit_log — append-only
- `user_id text`, `action audit_action not null`, `table_name text not null`, `record_id text not null`, `before jsonb`, `after jsonb`, `created_at`
- index `(organisation_id, table_name, record_id)`, `(organisation_id, created_at)`

### otp_rate_limits (if Better Auth's own rate limiting is insufficient for OTP; prefer Better Auth built-in — delete this table if unused)
- `phone text`, `window_start timestamptz`, `count integer`

## Multi-tenancy enforcement

Every query goes through a request-scoped `orgDb` helper that injects `eq(table.organisationId, ctx.orgId)`; raw drizzle access outside `src/lib/services` and `src/db` is forbidden by convention + ESLint restricted-import rule. Cross-org isolation test required (spec DoD).
